## 1. 背景与目标

在 DSH 中提供两种可切换的工作体验：

- **HARNESS**：当前 DSH 编码/Agent 工作区，保持现有功能和布局。
- **CHAT**：接近 DeepSeek 网页聊天的对话体验，复用 DSH 主框架，使用独立的对话导航和聊天主区。

CHAT模式入口不受DSH或官网登录状态限制；启动时可以默认HARNESS，整个`CHAT | HARNESS`控件保持可切换。未登录进入CHAT显示明确的官网登录按钮，仍由真实网站决定是否允许聊天。本插件不提供匿名聊天或本地/API替代聊天。

真实官网自行确认CHAT授权、显示和保存网页账号历史；插件不复制、合并或同步一份本地历史。DSH账号授权不决定CHAT入口权限。原生历史接口与网页实际加载/登录/两端一致性仍须分别验证。

## 3. 登录、授权与数据策略

当前产品沿用W025独立官网授权与模式规则、W026过渡恢复要求，并补充W027退出与重登显示规则。官网认证由真实页面确认，Client以统一status、revision和同一guest同步设置与对话页；unknown、短暂缺少导航/头像或结构不支持都不能推断登出，网络错误不能代替退出信号。

| 情况 | 模式与切换控件 | 数据/发送行为 |
|---|---|---|
| 启动官网授权待确认或Host能力不可用 | 默认HARNESS，切换器不因登录状态禁用 | 进入CHAT显示恢复状态、正常登录入口或真实连接错误 |
| 官网未登录 | 可以进入CHAT，保持用户模式选择 | 两处入口均进入同一guest正常登录，不开放匿名聊天 |
| 官网正常登录成功 | 保持当前CHAT/HARNESS，控件可用 | 立即同步公开账号/导航；记忆后台保存，保存状态不冒充官网登录状态 |
| 同一官网账号持续有效的授权状态更新（非页面重载） | 保持当前模式和同一guest | 统一status/revision，重复通知不重置对话/草稿 |
| 登录SPA过渡、unknown或暂缺导航 | 保持用户模式选择，不推断登出 | 首次5秒宽限；fallback持续只读安全结构探测，确认sidebar、新对话、layout/content后恢复适配，不因一次过渡永久保留双侧栏 |
| DSH退出、授权失效或切换账号 | 不禁用控件、不强制返回HARNESS | 不清除或复用独立CHAT授权；旧DSH公开id仅用于本插件旧记录精确迁移 |
| 在CHAT设置退出当前官网账号 | 保持当前模式，退出操作优先 | reset旧设置请求，建立保存/恢复barrier，先清记忆再官网logout；清除旧公开账号/列表并同步两处状态 |
| 官网网页内部退出或官网确认授权失效 | 保持当前模式，呈现正常登录入口 | 清除当前官网记忆与公开状态，禁止迟到保存/恢复重登旧会话 |
| 网络超时、断网、服务错误 | 不当作退出、不强制改变模式 | 区分连接错误与正在登录/恢复；固定错误可重试，不显示过期账号假状态 |
| 再次正常官网登录 | 保持当前模式 | 同一guest确认结果立即同步两处；不要求进入设置刷新或等待记忆写入后才能显示 |
